# サインアップアプリ

[English](README.en.md)

Google Apps ScriptとGoogle Sheetsで構築した、無料のオープンソースボランティア募集アプリです。日本の学校におけるイベントのボランティア募集を想定して作成しました。

---

## 主な機能

- デスクトップとモバイルに対応したレスポンシブなカード形式のスケジュール
- 検索しやすい「さがす」表示と、一日の流れを確認できる「まとめ」表示を切り替え可能
- 活動、役割、複数の時間帯、キーワードによる共通の絞り込み機能
- スクロール中も必要なタブと絞り込み欄を固定表示し、デスクトップでは画面幅に応じてコンパクトな1行の絞り込み欄を使用
- デスクトップでは空き枠数と現在の登録数／定員を集計し、クリックで詳細一覧を表示
- 空き枠と現在の登録の両方の詳細一覧で、活動別のカラーリボンを表示
- 役割別の「募集中」チップと活動別のアクセントカラーで、空き枠を見つけやすく表示
- 時間帯の範囲表示（スロット／カード、例：9:00 am - 10:00 am）
- 4つのボランティア役割 — 「一般保護者」「学年委員」「役員、運営・実行委員」「実行委員」（名称変更可能）
- 役割ごとの定員管理 — 役割ごとに独自の定員を設定
- 任意のActivityLimitsタブで、活動ごとに1人あたりの申込み上限を設定可能
- 定員が0の役割は自動的に非表示
- 役割ごとのカラーコード — 緑（一般保護者）、琥珀（学年委員）、青（役員、運営・実行委員）、紫（実行委員）
- スケジュールカード内の名前を役割ごとに表示
- 名前とクラスで申込み — Googleアカウント不要
- 日本語の名前は空白を除いて保存・照合し、日本語以外の名前の単語間スペースは保持
- モーダルの一覧から自分の申込みを選択してキャンセル可能
- 確定した申込みとキャンセルを表示中のスケジュールとモーダルへ直ちに反映。キャンセル後はバックグラウンドでサーバーの最新データと照合し、その更新を適用できない場合のみページを再読み込み
- 申込みとキャンセルはブラウザ側で同時に1件のみ送信し、繰り返し操作による重複リクエストを防止
- 短時間のロック競合は、書き込みが開始されていないことをサーバーが明示し、取得時のモーダルセッションが有効な場合に限り、最大1回だけ再試行。それ以外の失敗は自動再試行しない
- 申込みモーダルで役割ごとに名前をグループ表示
- スロットをクリックするとメモも表示
- サーバーサイドで定員管理（競合状態の防止）
- 同一スロット、時間が重なるスロット、上限対象の活動で、名前に基づく重複申込みを防止
- 活動／カードごとにサブタイトルと場所を表示（担当者・部屋など）
- スケジュールカードとモーダルにメモ・説明を表示
- 既存の申込みがあるスロットにヒントテキストを表示
- Google Sheetの名前がページタイトルに自動反映
- URLパラメータで複数イベントに対応 — 再デプロイ不要
- 選択したスケジュール表示を次回アクセス時まで記憶
- 名前とクラスはUnicodeの文字・数字、空白、および限定された記号に対応。絵文字や単独の結合文字など任意のUnicode入力には非対応
- データはGoogle Sheetsに保存 — 管理が簡単
- 無料 — Googleアカウントがあればホスティング費用不要

## 仕組み

```
マスター管理シート（Configタブ）
      ↓ エイリアスの照合
イベント用Google Sheet（Events・Signupsタブ、任意のActivityLimitsタブ）
      ↓
Google Apps Script（バックエンド＋Webサーバー）
      ↓
公開Webアプリ（ユーザーのログイン不要）
```

管理者はGoogle Sheetsでイベントを直接管理します。ユーザーはイベントのエイリアスパラメータ付きURLにアクセスし、空きスロットを確認して名前とクラスを入力して申し込みます。同じモーダルからキャンセルも可能です。すべてのデータはリアルタイムでイベントのGoogle Sheetに書き込まれます。

## 必要なもの

- Googleアカウント
- [Node.js](https://nodejs.org)（LTSバージョン）
- [CLASP](https://github.com/google/clasp) — GoogleのApps Script CLI
- [VS Code](https://code.visualstudio.com) またはその他のテキストエディタ
- Git（バージョン管理用、任意）

推奨： このアプリには個人アカウントではなく、専用のGoogleアカウントの使用を推奨します。アプリはアカウントオーナーとして実行されるため、すべてのSheetへのアクセスとスクリプトの実行がそのアカウントで行われます。専用アカウントを使用することで、個人データを分離し、同僚と管理者アクセスを共有しやすくなり、アプリのクォータが超過した場合でも個人のGoogleサービスへの影響を防ぐことができます。

## セットアップ手順

### ステップ1 — マスター管理シートの作成

1. [sheets.google.com](https://sheets.google.com) で新しいスプレッドシートを作成
2. 任意の名前をつける（例：**サインアップアプリ管理**）
3. **Config** というタブを作成（大文字のCで始まること）
4. 1行目にヘッダーを追加：

| A           | B        | C      |
| ----------- | -------- | ------ |
| Event Alias | Sheet ID | Status |

5. URLからSheet IDを確認：

```
https://docs.google.com/spreadsheets/d/YOUR_MASTER_SHEET_ID/edit
```

6. 共有設定を**制限付き**に設定 — 編集できるのは権限を付与した管理者または編集者のみ

### ステップ2 — イベントシートの作成

1. 新しいスプレッドシートを作成（または既存のものを複製）
2. 任意の名前をつける — この名前がアプリのページタイトルになります
3. 以下の2つの必須タブを作成。活動ごとの申込み上限が必要な場合のみ、任意タブも追加：

**Eventsタブ** — 1行目にヘッダーを追加：

| A       | B        | C        | D    | E         | F       | G           | H        | I            | J             | K                      | L                 |
| ------- | -------- | -------- | ---- | --------- | ------- | ----------- | -------- | ------------ | ------------- | ---------------------- | ----------------- |
| EventID | Activity | SubTitle | Date | StartTime | EndTime | Description | Location | GeneralSlots | ClassRepSlots | SteeringCommitteeSlots | OrgCommitteeSlots |

**Signupsタブ** — 1行目にヘッダーを追加：

| A        | B       | C    | D     | E    | F         |
| -------- | ------- | ---- | ----- | ---- | --------- |
| SignupID | EventID | Name | Class | Role | Timestamp |

**ActivityLimitsタブ（任意）** — 1行目にヘッダーを追加：

| A        | B            |
| -------- | ------------ |
| Activity | MaxPerPerson |

1人あたりの申込み上限を設ける活動のみ、1活動につき1行追加します。例えば、`競技ボランティア`の`MaxPerPerson`を`1`にすると、同じ参加者がその活動に申し込めるのは1枠までです。記載していない活動には上限を設けません。このタブが存在しない場合、またはヘッダー行のみの場合は、活動ごとの上限を適用せず従来どおり動作します。

4. Eventsタブにイベントデータを入力。不要な役割のスロット数は`0`に設定。
5. URLからSheet IDを確認。
6. 共有設定を**制限付き**に設定 — 編集できるのは権限を付与した管理者または編集者のみ。

### ステップ3 — ConfigタブへのイベントIDの登録

1. **マスター管理シート** → **Configタブ** を開く
2. 新しい行を追加：

| Event Alias | Sheet ID            | Status |
| ----------- | ------------------- | ------ |
| myevent     | YOUR_EVENT_SHEET_ID | OPEN   |

**Status**列に、`OPEN`と`READ_ONLY`のみを含むGoogle Sheetsのプルダウンを設定してください。ConfigタブまたはStatus列を保護し、管理者だけが変更できるようにします。Statusが未入力または不正な場合は、安全のため`READ_ONLY`として扱われます。スケジュールは表示されますが、公開アプリからの申込みとキャンセルは拒否されます。

### ステップ4 — Apps Script APIの有効化

[script.google.com/home/usersettings](https://script.google.com/home/usersettings) にアクセスし、**Google Apps Script API** をオンにする。

### ステップ5 — CLASPのインストール

```bash
npm install -g @google/clasp
clasp login
```

### ステップ6 — リポジトリのクローン

```bash
git clone https://github.com/endotaatodne/signup_app.git
cd signup_app
```

### ステップ7 — Apps Scriptプロジェクトの作成

```bash
clasp create --title "Signup App"
```

`clasp create`を実行すると、リポジトリルートにローカル用の`.clasp.json`が作成されます。このファイルは、`clasp push`や`clasp deploy`が更新するApps Scriptプロジェクトとローカルのチェックアウトをひも付けます。Apps ScriptプロジェクトのスクリプトIDが含まれるため、ローカル専用として扱い、コミットしたり、Issueなどに貼り付けたり、他の人と共有したりしないでください。このリポジトリでは`.clasp.json`を`.gitignore`に含めています。

新規作成ではなく既存のApps Scriptプロジェクトにこのチェックアウトを接続する場合は、ローカルで`.clasp.json`を作成または更新します。共有する文書には実際のIDを書かず、形式は次の例を参考にします：

```json
{
  "scriptId": "YOUR_SCRIPT_ID",
  "rootDir": "."
}
```

スクリプトIDはApps Scriptの**プロジェクトの設定** -> **スクリプト ID**で確認し、`YOUR_SCRIPT_ID`を置き換えて保存します。Sheet IDやデプロイメントIDではなく、Apps Scriptプロジェクト自体のスクリプトIDを指定してください。

### ステップ8 — スクリプトプロパティの設定

マスターシートIDはスクリプトプロパティに安全に保存します。

1. [script.google.com](https://script.google.com) でサインアップアプリのプロジェクトを開く
2. **プロジェクト設定**（歯車アイコン）→ **スクリプトプロパティ** をクリック
3. **スクリプトプロパティを追加** をクリックし、以下を追加：

| プロパティ        | 値                          |
| ----------------- | --------------------------- |
| `MASTER_SHEET_ID` | `your_master_sheet_id_here` |

4. **スクリプトプロパティを保存** をクリック

### ステップ8b — Config.gsで役割名を設定

`Config.gs`を開き、役割名を変更する場合は`ROLES`定数を更新：

```javascript
const ROLES = {
  general: "一般",
  classRep: "クラス代表",
  steeringCommittee: "役員、運営・実行委員",
  orgCommittee: "実行委員",
};
```

キー（`general`、`classRep`、`steeringCommittee`、`orgCommittee`）はそのままにして、右側の値のみ変更してください。

### ステップ9 — コードのプッシュ

```bash
clasp push
```

このコマンドはローカルの`.clasp.json`を読み取り、どのApps Scriptプロジェクトを更新するかを判断します。ファイルがない場合やスクリプトIDが間違っている場合、`clasp push`は失敗するか、意図しないプロジェクトを更新してしまいます。

### ステップ10 — Webアプリとしてデプロイ

1. [script.google.com](https://script.google.com) でサインアップアプリのプロジェクトを開く
2. **デプロイ** → **新しいデプロイ** をクリック
3. 歯車アイコン → **ウェブアプリ** を選択
4. 以下を設定：
   - **次のユーザーとして実行：** 自分
   - **アクセスできるユーザー：** 全員
5. **デプロイ** をクリック
6. 権限の承認を求められたら許可
7. `/exec` で終わるWebアプリのURLをコピー
8. 今後の再デプロイのために**デプロイメントID**をメモ

## イベントリンクの共有

各イベントは`?event=`パラメータを使った独自URLを持ちます：

```
https://script.google.com/.../exec?event=myevent
```

URLのエイリアスはConfigタブの**Event Alias**列と完全に一致している必要があります（大文字・小文字は区別しません）。

パラメータなしでURLにアクセスした場合は「イベントが指定されていません」というメッセージが表示されます。

## スケジュールの使い方

- **さがす**では、時間帯ごとに詳しい申込みカードを表示します。活動、ボランティアの役割、1つ以上の時間帯（該当する募集枠が満員の時間帯を含む）、または募集内容・登録者名に一致するキーワードで絞り込めます。デスクトップでは、活動と役割のボタンを押すと、選択肢がボタン形式のパネルで表示されます。選択後もパネルは開いたままとなり、パネル外をクリックするかEscapeキーを押すと閉じます。
- **まとめ**では、一日の予定を時間順のコンパクトな一覧で表示します。活動別のアクセントカラーと役割別のチップで、残りの空き枠を確認できます。
- デスクトップでは、絞り込み欄の上に全体の空き枠数と現在の登録数／定員を表示します。絞り込み中は、現在表示している結果の集計も併記します。
- デスクトップの集計欄をクリックすると、空き枠または現在の登録を時間順で確認できます。絞り込み中は**全体**と**現在の絞り込み**を切り替えられ、詳細を選ぶと該当スロットの登録／キャンセル画面が開きます。
- スクロール中もスケジュール操作欄は表示されます。デスクトップでは、十分な画面幅がある場合は絞り込み欄をコンパクトな1行で表示し、狭い画面では2行に切り替えます。「さがす」または「まとめ」の選択はブラウザに保存され、次回も引き継がれます。

日本語の文字を含む名前を入力した場合、半角・全角を含む空白はブラウザとバックエンドの両方で一貫して削除されます。たとえば`山田 太郎`は`山田太郎`として保存されます。日本語の文字を含まない名前では、単語間に正規化された半角スペースが1つ保持されます。

同一スロットへの重複申込み、時間が重なる申込み、および活動ごとの上限を確認する際は、バックエンドが正規化済みの名前からサーバー専用のNFKC識別キーを生成します。このため、全角・半角のラテン文字など、互換上同じ表記は同一の参加者として扱われます。この追加の識別用正規化は、従来の表示・保存時の正規化やブラウザの絞り込みには影響しません。クラスは自由入力の情報として保存・表示され、クラスを変更してもこれらの確認では別の参加者として扱われません。

キャンセルでは、まず名前とクラスを厳密に正規化した照合段階を使用します。従来互換およびNFKC互換の照合段階は、一致する行が1件だけの場合に限り採用し、複数行が一致する場合は任意の申込みを削除せず拒否します。成功時には、削除した行の実際の名前と表示用クラスが返されるため、ブラウザはその表示行を直ちに削除できます。古い応答との互換用照合も、一致が1件だけの場合に限定されます。

サーバーが申込みまたはキャンセルの成功を確定すると、現在のスケジュール、集計、モーダルの状態へ直ちに反映されます。キャンセル成功後は、確認表示を遅らせることなく、バックグラウンドでサーバーの最新グリッドデータを取得し、同時に行われた変更も反映します。その更新を適用できない場合は、デプロイ済みのイベントページを再読み込みします。いずれかの処理中に操作を繰り返しても、別のリクエストは開始されません。250ミリ秒のロック取得で、書き込み前の競合を示す明示的な`busy_retryable`が返され、取得時のモーダルセッションが引き続き有効な場合のみ、ブラウザは400〜799ミリ秒後に最大1回再試行します。一般的なサーバー応答や通信エラーは自動再試行しません。

## イベントの管理

### 新しいイベントの追加

1. Google Driveで既存のイベントシートを複製
2. **Eventsタブ**と**Signupsタブ**のデータ行をクリア（ヘッダーは残す）
3. シート名を更新 — これがページタイトルになります
4. 複製された**ActivityLimitsタブ**の設定が新しいイベントに合うように、確認・変更または削除
5. 新しいSheet IDをメモ
6. **マスター管理シート** → **Configタブ** を開く
7. エイリアス、Sheet ID、および初期Statusの`OPEN`を新しい行に追加
8. 新しいURLをユーザーと共有 — 再デプロイ不要

### イベントの編集

該当するシートの**Eventsタブ**の行を直接編集します。変更は次のページ読み込み時に反映されます。活動名を変更または削除する場合は、対応する**ActivityLimitsタブ**の行も同時に更新してください。

### 活動ごとの申込み上限

任意の**ActivityLimitsタブ**は、新しい申込みのたびにサーバー側で読み込み・検証されます。設定内容がブラウザに送信されることはありません。

- A列とB列のヘッダーには、それぞれ`Activity`と`MaxPerPerson`を使用します。
- 上限を設ける活動を1回だけ記載します。同じ活動を重複して記載することはできません。
- **Eventsタブ**の**Activity**列と同じ活動名を使用します。Eventsタブの活動名を参照するプルダウンをGoogle Sheetsで設定することを推奨します。
- `MaxPerPerson`には`1`や`2`など、1以上の整数を入力します。上限を設けない活動はこのタブに記載しません。
- 参加者は、表記を正規化した名前で照合されます。同じ名前による申込みは、同じ活動名を持つすべての枠について、日付・時間・クラス・役割にかかわらず合計されます。
- 申込みをキャンセルすると、活動の申込み数が1枠分すぐに戻ります。
- 上限を引き下げても既存の申込みは削除されません。変更後の上限以上に申し込んでいる参加者は、その活動に新しく申し込めなくなります。

上限に達した参加者には、対象の活動名と1人あたりの上限数を案内します。時間が重なる申込みにも該当する場合は、より具体的な活動ごとの上限メッセージを先に表示します。活動の上限に達していない場合は、同一スロットへの重複申込みと時間が重なる申込みの確認が引き続き別々に適用されます。

ヘッダー、活動名、重複、または上限値に誤りがある場合、新しい申込みは停止し、参加者には主催者への問い合わせをお願いする一般的なメッセージのみ表示します。スケジュールの表示とキャンセルは引き続き利用でき、設定エラーの詳細は管理者向けのApps Script実行ログに記録されます。

### イベントを閲覧専用にする

マスター管理シートの**Configタブ**で、イベントの**Status**を変更します：

- `OPEN`では、公開アプリからの申込みとキャンセルが可能です。
- `READ_ONLY`では、スケジュールと既存の申込み情報は表示されますが、新しい申込みとキャンセルの両方が拒否されます。

Statusはバックエンドで強制され、申込み行の追加または削除の直前にも最新値を確認します。すでにページを開いている利用者もロックを回避できません。ブラウザには閲覧専用の案内が表示され、申込みとキャンセルの操作欄が非表示になります。`OPEN`に戻すと、コードを再デプロイせずにイベントを再開できます。

対応する2つの値だけを含むプルダウンを使用してください。空欄、スペルミス、未対応の値は`READ_ONLY`として扱われ、詳細は非公開ログに記録されます。既存環境へこのバージョンをデプロイする前に、C列へ`Status`ヘッダーを追加し、引き続き書き込み可能にするすべてのイベントを`OPEN`に設定してください。

### イベントの削除

**Configタブ**から行を削除するとイベントURLはすぐに無効になります。必要に応じてGoogle DriveからイベントシートをDeleteしてください。

### 申込み状況の確認

各イベントシートの**Signupsタブ**に以下の情報が記録されています：

- 申込みID
- イベントID
- 参加者氏名
- 参加者クラス

## セキュリティについて

- すべてのGoogle Sheetsは**制限付き**共有に設定 — アクセスできるのは権限を付与した管理者または編集者のみ
- Webアプリはデプロイ者として実行 — 匿名ユーザーはSheetsに直接アクセス不可
- 活動ごとの上限設定はサーバー側で検証・適用され、ブラウザには送信されません
- `MASTER_SHEET_ID`はスクリプトプロパティに保存
- `.clasp.json`はApps ScriptプロジェクトのスクリプトIDを含むローカル専用のCLASP設定です。`.gitignore`に含まれており、バージョン管理したり共有したりしないでください
- Configタブに登録されたSheet IDのみ読み込み可能 — 未登録のSheet IDは拒否
- イベントのStatusはサーバー側で検証・強制され、未入力または不正な値は`READ_ONLY`として扱われる
- シート識別子はサーバーサイドでイベントエイリアスから導出 — クライアントからSheet IDを直接送信しない
- 入力の文字数と文字種類をクライアント・サーバー両側で検証
- `eventId`は厳格な正の整数として検証
- 申込み時のブラウザ側ハニーポットとページ読み込み後3秒の待機は、低負荷な補助チェックです。直接呼び出すクライアントはどちらも迂回でき、認証、CAPTCHA、またはセキュリティ境界ではありません
- 申込みとキャンセルの変更処理を多層の固定時間枠で保護。正確な範囲と消費時点は下記を参照
- `LockService`は250ミリ秒のロック取得で変更を直列化し、書き込み前の明示的な`busy_retryable`で、取得時のモーダルセッションが有効な場合だけ、ブラウザで400〜799ミリ秒後に最大1回再試行
- ブラウザ側の単一実行ガードは再試行が完了するまでリクエストを保持し、一般的なサーバーエラー、結果が不明な失敗、通信エラーはそこで終了
- ロック中の最新データからイベントポリシーと処理条件を最終確認し、確定したSheet変更をロック解放前にフラッシュ
- 役割の検証はサーバーサイドで正規の設定値との完全一致を要求 — クライアントからの不正な役割は拒否
- テンプレート値はBase64でエンコードし、構造化データはJSONとして直列化・解析。画面上の値は`textContent`で設定し、HTMLとして解釈したり破壊的に書き換えたりせず、検証済みの文字列を正確に保持
- バックエンドのキャンセルは名前・クラスの厳密な一致を優先し、従来互換またはNFKC互換の一致は1件だけの場合に限定し、衝突時は拒否
- ユーザーへのエラーメッセージは汎用的なものを使用 — 内部の詳細はログに非公開で記録

### 変更処理のレート制限

3層とも、最初に数えたリクエストから始まる固定時間枠を使用します。対象Sheet、EventID、操作ごとに独立しているため、`signup`と`cancel`が互いの許容量を消費することはありません。

- **参加者単位の試行上限：** 60秒間の最初の3回を許可し、4回目以降を拒否します。範囲にはNFKCで正規化した名前とクラスの組も含まれ、キャッシュキーには平文ではなく、長さを区切った組のSHA-256ダイジェストだけを保存します。この回数は、初期検証と緊急ヒューズを通過して`ScriptLock`を取得した後、ロック中の完全な処理条件を確認する前に消費されます。そのため、形式が正しい試行は、満員、重複、時間競合、照合の曖昧さ、登録なし、設定不備、または処理中にREAD_ONLYへ変更されたことにより後で拒否されても回数に含まれます。不正な入力、未知または初期状態でREAD_ONLYのイベント、終了済みイベントへの申込み、既にキャッシュで拒否されている試行、緊急ヒューズによる拒否、ロック競合またはロックサービス障害は、この参加者単位の許容量を消費しません。
- **緊急試行ヒューズ：** 10秒間の条件を満たす最初の100回を許可し、101回目以降を拒否します。このキャッシュ専用カウンターは、同じSheet／EventID／操作の範囲内で全参加者が共有します。ロック取得の直前に消費されるため、明示的なビジー応答やロックサービス障害も回数に含まれます。ブラウザが許可された再試行を実際に送信した場合、その再試行は緊急ヒューズでは別の1回です。ただし、ロックを取得して先へ進まない限り、参加者単位または永続上限は消費しません。
- **永続的な検証済み書き込み上限：** 60秒間の完全に検証された最初の20回の書き込み許可を認め、21回目以降を拒否します。`ScriptLock`内で最終ポリシーと処理条件を確認した後、`appendRow`または`deleteRow`の直前に消費します。それ以前の検証や処理条件による拒否は回数に含まれません。Sheet呼び出しより先に許可を記録するため、その後の追加、削除、またはフラッシュが失敗しても1回を消費することがあります。フラッシュ失敗後は、変更が反映されたか不明な場合があります。

参加者単位と緊急ヒューズのカウンター、および永続上限の拒否状態を一時保存するミラーには`CacheService`を使用します。これらはリソース保護を目的とする補助的な仕組みであり、Googleによって予定より早く削除される場合があり、キャッシュ障害時は許可側に倒れます。スクリプトプロパティ内の永続カウンターはロック中の正式な判定として残り、更新できない場合は安全のため書き込みを拒否します。各固定時間枠は、試行のたびに終了時刻が後ろへ延びる方式ではありません。

通常、申込みまたはキャンセルを1回行う利用者がこれらの制限を意識することはありません。同じ名前とクラスで形式上正しい失敗を繰り返すと、参加者単位の4回目の上限に達することがあります。短いグローバルロック競合では、取得時のモーダルセッションが有効な間に限り、最大1回の限定的な再試行が行われる場合があります。それでも競合する場合は、重複する変更を自動送信せず安全なエラーを表示するため、時間を置いて再度操作してください。

### レート制限が作成するスクリプトプロパティ

管理者が設定する`MASTER_SHEET_ID`に加えて、リクエストが永続的な書き込み許可まで到達すると、`signup_app_rate_limit_v3_success_<action>_<sheet-id>_<event-id>`形式のプロパティが作成されます。JSON値に含まれるのは固定時間枠の開始時刻と回数だけで、参加者の名前やクラスは含まれません。期限切れのプロパティは、同じ範囲で次に検証済み書き込み許可へ到達して再利用されるまで残る場合があります。通常の運用では変更しないでください。削除するとその範囲の永続保護がリセットされ、編集すると保護が弱まる、強まる、長引く、または壊れる可能性があります。

以前の`signup_app_rate_limit_v2_*`プロパティはv3から参照されず、そのまま安全に残せるため、移行時の削除作業は不要です。一時的な参加者単位と緊急ヒューズのカウンターは`CacheService`にあり、スクリプトプロパティには表示されません。

### 公開デプロイに残る制約

これらの制御は変更処理の悪用を減らすもので、利用者を認証するものではありません。公開されたスケジュールとグリッド更新の読み取り経路は匿名のままで、変更処理用カウンターの対象外です。そのため、公開読み取りトラフィックによってApps ScriptとSheetsのクォータが消費される可能性があります。また、スケジュールに表示する参加者項目は公開データとして扱ってください。

アプリはプロジェクト全体で1つの`ScriptLock`を使用するため、異なるSheetやイベントの正当な変更処理同士も競合する場合があります。短いロック取得と最大1回の安全な再試行により通常利用者の待ち時間を制限しますが、アクセス集中時にイベントを分離するものではありません。CAPTCHA、確認済みの利用者ID、IP単位の制限、上流のエッジレート制限はなく、直接呼び出すクライアントはブラウザのハニーポットと3秒の待機を迂回できます。より強い悪用対策が必要なデプロイでは、アプリ内カウンターを認可境界とみなさず、アクセス制御または上流の保護レイヤーを追加してください。

現在の設計では、`MASTER_SHEET_ID`をソースコードではなくスクリプトプロパティに保存し、ローカルのCLASP設定をGitの対象外にしています。それでもリポジトリを公開する前に追跡中の変更を確認し、Sheetのエクスポート、認証情報、参加者記録、その他の機密データを追加しないでください。

Apps Scriptでは、ルート直下のすべての`.gs`ファイルが1つの共有グローバルスコープに読み込まれます。上記の分割は責務ごとの整理であり、ESモジュールではありません。ファイルをまたぐ初期化をトップレベル式に追加せず、グローバル名の重複も避けてください。`index.html`がHTMLパーシャルの読み込み順を定義し、DOMイベントの登録と初期描画を行う`ClientInit.html`は最後に読み込む必要があります。

### ソースの責務と処理の流れ

本番用ソースファイルの先頭には、そのファイルの責務と重要な依存関係を説明する`@fileoverview`があります。また、名前付きJavaScript関数の直前には、入力、戻り値、重要な副作用を説明するJSDocがあります。動作を変更した際はこれらの説明も更新してください。ソースドキュメント用テストにより、説明が誤って失われていないことを確認します。

主な実行経路は次のとおりです：

- ページ表示：`doGet`がイベント設定を解決し、検証済みのスプレッドシートデータを読み込み、公開用グリッドモデルを作成して`index.html`を描画します。テンプレートがマークアップとスクリプトを合成し、最後に`ClientInit.html`が画面操作を登録して初回描画を行います。
- スケジュール操作：`ClientFilters.html`が絞り込み状態と一致判定を管理し、`ClientSchedule.html`がレスポンシブなスケジュールを描画し、`ClientInsights.html`が現在表示されているイベントからデスクトップ用集計を作成します。
- 申込みまたはキャンセル：`ClientModal.html`がブラウザ側の入力を事前検証し、同時に1件だけ変更リクエストを送信します。`SignupService.gs`が信頼できるサーバー側で再検証し、多層レート制限を確認して、250ミリ秒の`ScriptLock`取得を試みます。ロック中に検証済みデータを再取得し、イベントポリシーと処理条件を最終確認して、追加／削除の直前に永続上限を消費し、確定した変更をフラッシュしてからロックを解放します。明示的な書き込み前ビジー応答だけが、取得時のモーダルセッションが有効な場合にクライアントで最大1回再試行されます。成功後は表示を直ちに更新し、キャンセルではバックグラウンドで最新グリッドデータとも照合します。ページ全体の再読み込みは、その更新を適用できない場合の予備手段としてのみ使用します。

必須シートは、宣言されたスキーマの列範囲に限定して読み込みます。同じサーバー実行内でConfigを繰り返し確認する場合は、開いたマスタースプレッドシートのハンドルを再利用しますが、Statusや参照先の変更を回避できないよう、変更処理の直前にはConfigの値を再度読み込みます。これはハンドルの再利用であり、イベントや申込みデータのキャッシュではありません。

末尾が`_`のサーバーヘルパーは、ブラウザ向けエントリーポイントではなく内部関数であることを示す規約です。公開するサーバー関数は`doGet`、`getGridDataForAlias`、`submitSignup`、`cancelSignup`、`getDeployedUrl`に限定しています。

## ユニットテスト

このプロジェクトには、ルート直下の複数の`.gs`ファイルに分割されたGoogle Apps Scriptバックエンドと、`index.html`およびHTMLパーシャルから構成されるフロントエンドを対象にしたローカルユニットテストが含まれています。

リポジトリのルートで次のコマンドを実行してください：

```bash
node --test --test-isolation=none test/*.test.js
```

シェルで`npm`スクリプトを実行できる場合は、次でも実行できます：

```bash
npm test
```

現在のテスト対象：

- サーバー側の`.gs`ファイル
  設定読み込み、申込み/キャンセル処理、多層レート制限、スプレッドシート検証、安全なテンプレート転送、正規化など
- 名前（日本語名の空白処理を含む）、クラス、数字、クラス区切り文字に関する共通の正規化処理
- `Client*.html`に分割されたクライアント側ロジック
  イベント索引の構築、レスポンシブ表示、スケジュールの絞り込みと表示モード、デスクトップ集計、キャンセル選択、メッセージ表示、クライアント側の正規化など
- 変更確定後の表示同期、申込み／キャンセルの単一実行、キャンセル後のサーバーデータ照合、および再読み込みへのフォールバック
- 個人を特定しない合成テストデータを使用した、スプレッドシートサービス呼び出し回数の決定的な検証
- すべての本番用ファイルと名前付き関数に対するソースドキュメントの網羅性

テスト戦略：

- 本番用の`.gs`または`.html`ファイル、特に共通のバリデーション/正規化ロジックを変更したら、毎回テスト全体を実行する
- 期待される挙動を変更した場合は、その変更と同じタイミングでテストも更新または追加する
- テストハーネスではルート直下のすべての`.gs`ファイルを読み込み、`index.html`から参照されるHTMLパーシャルを解決して、デプロイ対象と同じ構成を検証する
- Apps Script固有・ブラウザ固有の依存はテスト内でモックし、デプロイせずに本番ロジックを検証できるようにする
- ユニットテストは回帰防止として扱い、バグ修正時には修正前なら失敗していたテストを追加する

性能改善は、実際の参加者データではなく、モックしたサービスの決定的な呼び出し回数と合成テストデータで計測します。ローカルテストの実行時間は、Google Apps Scriptやネットワークの待ち時間を示すものではありません。デプロイ環境の所要時間を収集する場合は、許可した操作名と結果、処理時間の合計、および大まかなデータ件数区分だけを使用し、氏名、クラス、役割、エイリアス、Sheet ID、Event ID、検索文字列、メッセージ、行データは記録しないでください。

注意：現在のテストはユニットレベルの検証を対象としており、実ブラウザ上での操作テストを置き換えるものではありません。
